Why I built tt

2026-07-26

I kept four coding agents running at once — Claude Code here, Codex there, Cursor in a third tab — and spent more time hunting for the right terminal than reading what any of them wrote. Which one was still working? Which one had quietly exited twenty minutes ago? I'd lose a session by closing the wrong window.

So I built tt: a desktop app that puts every coding-agent CLI in one place. Add a project folder, spawn an agent in any directory, and they tile side by side automatically. Each tile gets a live activity dot (working / idle / exited) and a workflow status you set yourself — planning, in progress, in review, done — which colors the tile so you can see the state of everything at a glance. Click a tile to zoom into it.

Two decisions mattered. First, agents run inside tmux, so sessions survive closing and restarting the app; losing an hour of context to a stray Cmd-Q was the thing that annoyed me most. Second, it doesn't wrap the agents or try to be smart about them — it's Tauri plus xterm.js, real terminals, whatever CLI you have on your PATH. Claude Code, Codex, Cursor, Gemini, opencode, Antigravity, or just a shell.

It's macOS-only for now and the build is unsigned, so first launch needs a right-click → Open. Source and releases are on GitHub.
